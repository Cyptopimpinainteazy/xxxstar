# RUSTSEC-2026-0381 / RUSTSEC-2026-0383 — distrusted emSign root in webpki-roots

Published 2026-10-19 (CVE-2026-111943). `webpki-roots` and `webpki-root-certs` bundled
**emSign ECC Root CA - G3** (SHA-256
`86:a1:ec:ba:08:9c:4a:8d:3b:be:27:34:c6:12:ba:34:1d:81:3e:04:3c:f9:e8:a8:62:cd:5c:57:a3:6b:be:6b`),
which can accept certificate paths through distrusted emSign intermediates whose private
keys are now public. Upstream 1.0.10 removes that one root and changes nothing else
(measured: 121 → 120 anchors; the other three emSign roots are byte-identical).

The advisory's fixed range is `>= 1.0.10` only. Three things in this tree match it:

| Copy | Where from | Affected? | What this repository does |
|---|---|---|---|
| `webpki-roots` / `webpki-root-certs` **1.x** | rustls, hyper-rustls, sqlx, quinn | yes, below 1.0.10 | every lockfile in the tree is on **1.0.10** |
| `webpki-roots` **0.25.4** | `libp2p-websocket 0.44` ← `libp2p 0.54` ← polkadot-sdk `sc-network` | yes: its own `lib.rs` bundles G3 | built from `patches/webpki-roots-0.25.4`, G3 removed |
| `webpki-roots` / `webpki-root-certs` **0.26.11** | jsonrpsee 0.24, sqlx 0.8 | no: one-line re-export of 1.x, no roots of its own | resolves to 1.0.10 |

There is no patched 0.25.x or 0.26.12, and the polkadot-sdk and jsonrpsee pins cannot reach
1.x, so both advisories are ignored in `deny.toml` and `.cargo/audit.toml`. The ignore is
only valid while the facts above hold, so `tests/test_webpki_roots_distrust.py` (local-ci
gate `webpki roots distrust`) re-checks them and fails when:

* the vendored `lib.rs` contains G3, loses another anchor, or differs from the hash in
  `patches/webpki-roots-provenance.json`;
* the root workspace or `crates/x3-sidecar` (a nested workspace that does not inherit the
  root `[patch]`) resolves 0.25.x from crates.io instead of the patch;
* any lockfile resolves a 1.x below 1.0.10, or a 0.26 shim re-exports one;
* an unpatched pre-0.26 copy appears in a lockfile not named in its `UNPATCHED_PRE_026`
  list, each entry of which states why that workspace is not a shipped artifact.

The vendored crate is the crates.io archive (`sha256 5f20c57d…`, the checksum in
`Cargo.lock`) with the G3 entry removed from `src/lib.rs`; every other file is
byte-identical.

## Remaining exposure

Unpatched pre-0.26 copies remain in two Solana workspaces, through `solana-client`:
`programs/svm/x3_atomic_swap` (0.24.0, 0.25.4) and
`X3-contracts/svm/programs/x3_htlc/tests-live` (0.24.0, 0.25.4). Neither is a shipped
artifact; covering them needs a vendored 0.24 as well as `[patch]` entries in each of those
workspaces. `patches/sc-rpc-server/Cargo.lock` (0.25.2) and `patches/quinn-proto/Cargo.lock`
(webpki-root-certs 1.0.2) are vendored crates' own lockfiles, which cargo does not read.
