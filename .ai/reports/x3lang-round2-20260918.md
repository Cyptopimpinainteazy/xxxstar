# X3Lang round 2 — 2026-09-18

Three defects fixed, all on the path that matters. Baseline for this round was
485 passing tests; it is now 493, with clippy and fmt clean.

## 1. The lexer had no comment support (HIGH)

**Symptom.** Six of thirteen shipped `examples/*.x3` failed with
`Parser error: expected top-level item`.

**Cause.** `Lexer::lex_all_with_file` in `crates/x3-lexer/src/lexer.rs` had no
comment handling, so `//` lexed as two `Slash` operators and `/*` as
slash-then-star. Minimal proof:

| source | before |
| --- | --- |
| `intent a { }` | parses |
| `// c` + `intent a { }` | `expected top-level item` |
| `intent a {` `// c` `}` | `expected expression` |
| `/* c */` + `intent a { }` | `expected top-level item` |

**Fix.** Line comments (the terminating newline is left unconsumed, because the
grammar is newline-sensitive and swallowing it would merge two statements);
block comments (newlines inside still emit `Newline` tokens for the same
reason); and a fail-closed `Unknown` token for an unterminated block comment,
so a half-written comment cannot silently discard the rest of the program and
still report success. Eight unit tests in the lexer module.

**Effect.** `tests/e2e/bridge_step.x3` and `tests/e2e/simple_transfer.x3` went
from unparseable to compiling and running. No regressions.

## 2. The build path skipped every safety guard (HIGH)

**Symptom.** `x3c check` rejected a program; `x3c build` emitted bytecode for
it. Measured:

```
$ x3c check tests/conformance/invalid/routes/same_chain_bridge.x3
  4 errors, including "bridge from_chain == to_chain; cross-VM bridge must
  target a different chain"
$ x3c build --out /tmp/bad2.x3b <same file>
  x3c build: 280 bytes (70 ops) -> /tmp/bad2.x3b      <-- bytecode emitted
```

**Cause.** Two build paths existed and the *default* one was unverified.
`compile_with_mode` ran `verify_semantics`; `compile_source` was
`parse_source` + `compile_program` with no verification, and `cmd_build` in
`x3c` chooses `compile_source` whenever the mode is `dev` — the default.
Every guard in `semantic.rs`, including the finality and slippage guards added
earlier in this session, was therefore bypassable by the path that produces
executable bytecode.

**Fix.** `compile_source` now delegates to `compile_with_mode(source,
CompilationMode::Dev)`. `lower_program(program, ctx)` is literally
`lower_program_with_mode(program, ctx, CompilationMode::Dev)`, so lowering is
unchanged — the change only adds the verification that was missing. Also
replaced the hardcoded `8, 4` verifier budgets with
`DEFAULT_MAX_ATOMIC_OPS`/`DEFAULT_MAX_ROUTE_HOPS`, and made the failure message
list every violation instead of only a count.

**Proof after the fix.**

```
REFUSED (exit=2)  same_chain_bridge.x3          (no output file)
REFUSED (exit=2)  bridge_without_finality.x3    (no output file)
REFUSED (exit=2)  swap_without_slippage.x3      (no output file)
ACCEPTED          internal_swap.x3              -> 408 bytes (102 ops)
```

## 3. Shipped examples that were genuinely unsafe

Making the build path verify surfaced fixtures that were only "passing"
because nothing checked them. Each was fixed rather than exempted:

- `examples/simple_swap.x3` — bridge with no nonce, no refund path, no finality.
- `examples/staking_intent.x3` — bridge with no nonce, no refund path.
- `examples/multi_leg_route.x3` — three bridges with no nonce, timeout, or finality.
- `examples/timeout_refund_minimal.x3` — bridge with no nonce or finality.
- `compiler/tests/test_control_flow_e2e.rs` — inline swap intent with no
  slippage bound and no refund path.

## 4. Shared-tree repair

The workspace did not compile when this round started:
`compiler/src/opportunity.rs:513` moved `leg` into `path.push(leg)` and then
read `leg.output`. Fixed without a clone by reading `leg_output` before the
move. `cargo fmt --all` was also applied to `opportunity.rs` (whitespace only)
because the fmt gate covers the whole workspace.

## Cross-round lesson

Three of the four defects above share one shape: **a safety check that exists
but is not on the path that matters.** The finality guard warned instead of
erroring and the warning was discarded; the proof guard warned and its
expected names match no real program; the verifier was not called by the build
path. Reading a check's presence as coverage is the recurring mistake here.
