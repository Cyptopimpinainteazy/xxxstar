## The design decision that shapes the rest

A dry run has no prices, so the compiler's economic guards are *measured* guards: the
artifact refuses with `X3_GUARD_UNMEASURED` unless a host states what the market did.
On the command line that was `--measured-profit-bps`, one number for a whole trade.
PHASE 54 wants the accounting, so the snapshot states the observations separately and
the report **derives**:

| figure | where it comes from |
|---|---|
| net | `gross − capital − fees`, checked — never a stated field, because a stated net could disagree with its own components |
| net in bps | `Ratio::of(capital, net).to_bps(Down)` — PHASE 43's vocabulary, not a bare ten-thousand division |
| minimum required | the **artifact's** floor in bps applied to the snapshot's capital (`Bps::of_floor`) |
| result | that comparison, or `NO FLOOR STATED` |

The floor is read from the artifact's own instructions. A caller who could state the
requirement could make any run pass.

`--state` and `--measured-*` are the same fact stated two ways, so stating both is
refused rather than reconciled.

## Refusals, and what each names

| snapshot | refusal |
|---|---|
| schema version ≠ 1 | the version, and why a partial read is not taken |
| an unknown field | refused via `deny_unknown_fields` — a misspelled field is a state the host meant to state and this build cannot see |
| components in different assets | the field, its asset, the capital's asset |
| `gross < capital + fees` | all three figures, because a shortfall a reader cannot see is one they cannot act on |
| zero capital | **by name** — see below |
| a slippage ceiling with no slippage | the ceiling |
| a venue outside every approved list | the venue and the list |
| empty route | that a route of nothing is not one |

Zero capital is its own variant because `Ratio::of` refuses it with the same `None` it
uses for a value that does not fit: the first version reported `"amount": 0` as
"capital and net are too large to express as a ratio of one another". The compiler
caught it — the variant was never constructed — which is the dead-code warning doing
the job it is for.

Two things are reported honestly rather than implied:

- an artifact that states no profit floor reports `NO FLOOR STATED`, not `PASS`. A
  strategy with no floor can lose money and still settle, and calling that a pass would
  be the report congratulating a program for stating nothing;
- an artifact that declares no approved venue list reports that the observed venues
  were **not** checked, rather than leaving a reader to assume they were.

## The defect this found in the shared opcode spec

`REQUIRE`'s flags byte carries two things: the comparison mode in bits 0-1 and the
guard's own operator in bits 2-4.

`spec/opcodes.rs` had the **writer** (`require_flags`) and a **reader for the operator**
(`require_guard_operator`) — but no reader for the mode, so the VM and the disassembler
each masked inline:

```
vm/src/executor.rs:357      let satisfied = match _flags & REQUIRE_COMPARE_MASK
compiler/src/emitter.rs:1322  let mode = match flags & REQUIRE_COMPARE_MASK
```

and this command's first version compared the **raw** byte:

```
before  x3c simulate --explain, on an artifact with a 20bps floor and an 8bps ceiling
        Minimum required: none — the artifact states no profit floor
        Result: NO FLOOR STATED (net 2500bps)
after   Minimum required: 2,000 ethereum.USDC (20bps of capital)
        Slippage: 6bps against a ceiling of 8bps — within
        Result: PASS (net 2500bps)
```

The flags byte for a measured profit guard with `>=` is `2 | (4 << 2)` = `18`, so
`flags == 2` never held. This is the third time in this session that a set named in N
places drifted in N−1 of them (`CHOICE_CRITERION_*`, `REQUIRE_COMPARE_*`, the metadata
records). The fix is the missing reader:

```rust
pub const fn require_comparison(flags: u8) -> u8 { flags & REQUIRE_COMPARE_MASK }
```

used by the VM, the disassembler and the simulation, with a round-trip test over every
mode × operator pair that fails if either side gains a variant alone.

## Fidelity: the phase's own numbers

The spec's worked example is a unit test of both the arithmetic and the rendered
report, figures and grouping included: capital 2,000,000, gross 2,019,842, fees 8,119,
floor 50bps → net 11,723, **58bps**, minimum 10,000, `PASS`. The test asserts the
report contains `Capital:\n2,000,000 USDC`, `Net:\n11,723 USDC`,
`Minimum required:\n10,000 USDC (50bps of capital)` and `Result:\nPASS (net 58bps)`.

## Determinism (PHASE 42, which this phase sits on)

Nothing in the report reads a clock, a random source or a hash map: the fields are
`Vec`s in document order, every operation is integer, and `render` is a pure function
of the outcome. A test renders the same outcome nine times and asserts byte-identical
output.
