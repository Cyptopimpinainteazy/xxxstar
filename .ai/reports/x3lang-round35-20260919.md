# X3Lang round 35 — 2026-09-19 — a timeout's unit is the unit enforced (TICKET-033)

Landed on `master` as `99f0ca42a` (base `1dcd17d58`). Closes TICKET-033.

## What the language said, and what it did

| written | meant | should mean |
|---|---|---|
| `timeout 180s` | 180 blocks (18 minutes) | 30 blocks (3 minutes) |
| `timeout 40m` | 40 blocks (4 minutes) | 400 blocks (40 minutes) |
| `timeout 3600s` | 3600 blocks (6 hours) | 600 blocks (1 hour) |

The suffix was decoration. The lexer hands `40m` over as a single identifier,
`lowering` took the leading digits and ignored the rest, and the atomic swap's
ordering invariant read the *same field* as **seconds** while lowering read it as
**blocks** — and skipped any expression it could not read, which is every
expression with a unit. So the invariant the ticket was deferred for was not
"moved": for any program that wrote its units, it was not being checked at all.

## One model, in one place

- **Classification at the source.** The parser's `parse_duration_expr` turns
  `180s`, `40m`, `2h`, `1d`, `500ms` into `LiteralExpr::Duration { value, unit }`,
  keeps a bare number as a count of blocks, accepts `40 blocks` as the same
  count, refuses an undefined unit (`40x`) **by name**, and refuses a fractional
  duration (`40.5s`) rather than truncating it. Three call sites use it: the
  intent `timeout` clause, the `atomic swap` `timeout source|destination` clause,
  and `on_timeout`.
- **One conversion.** `lowering::timeout_expression_to_blocks` reads units and is
  the only thing that does. `SECONDS_PER_BLOCK = 6` is named once and
  `MAX_TIMEOUT_BLOCKS` is *derived* from it (24 hours of blocks), replacing a
  second hardcoded `14400` in `semantic.rs` that carried its own comment about the
  block time. Two numbers that had to agree now cannot disagree.
- **Rounding up.** 45s is 7.5 blocks and becomes 8; 500ms becomes one block
  rather than none. A window shorter than the program asked for is the dangerous
  direction in an HTLC.
- **The ordering invariant compares blocks**, which is what it enforces, and it
  now sees units: `timeout source 20m / destination 40m` is rejected (before, the
  units made it invisible).
- **The ceiling applies everywhere.** Dev-mode lowering refuses a window over a
  day; before, an intent's timeout had no ceiling at all and only the `atomic
  swap` clause and the mainnet pass checked.
- The `OnTimeout` lowering lost its own inline conversion, which clamped an
  oversized literal to `u32::MAX` — a silently different deadline rather than a
  refusal.
- `extract_seconds_from_expr` (the second, seconds-based reader of the same
  field) is deleted with its doc comment, rather than left as a second opinion.

## The two tests that encoded the old semantics

Both are updated to *derive* the expectation from `SECONDS_PER_BLOCK` and to say
why the number is what it is, rather than restating it:

- `test_fusion.rs::the_earliest_deadline_is_the_ring_deadline` — the ring's
  members declare 20s/25s/30s, so the earliest is four blocks, not twenty.
- `vm/tests/test_e2e_examples.rs::minimal_intent_lowers_with_atomic_and_timeout` —
  `timeout 45s` is eight blocks, not 45.

Neither was weakened: each asserts the block time's value *and* the converted
expectation.

## What this round did not do

- `parse_deadline_expr` (the trading `deadline: N blocks` form) still reads its
  own unit and does not accept `2h`. It is the same class of problem in a
  different clause; TICKET-048 records it rather than leaving it unsaid.
- TICKET-027's run-time half stands: the emitter still writes `STATIC` for every
  guard. This round's ordering fix is compile-time; **no** guard is compared
  against a run-time quantity. The next step there is per-kind, and the ticket
  now has the classification it needs (`SolverBond` and `RelayerQuorum` already
  have compile-time evaluations; `Nonce`, `Slippage`, `Finality` and the rest do
  not).
