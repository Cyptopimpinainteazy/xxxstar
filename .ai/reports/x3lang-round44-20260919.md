# X3Lang round 44 — 2026-09-19 — gas charges for the payload it reads (TICKET-056)

Landed on `master` as `1c9d54812` (base `4e2890c63`).

## The fifth table

`gas_surcharge` charged `payload_len / 32` for a list of ranges that omitted
instructions whose payloads both the verifier and the executor read and dispatch:

| instruction | opcode | charged before |
|---|---|---|
| `ATOMIC_CHOICE` | 0x53 | nothing |
| `ROUTE_FALLBACK` | 0x54 | nothing |
| `PARALLEL_PLAN` | 0x55 | nothing |
| `STRATEGY_LICENSE` | 0x57 | nothing |
| the trading range | 0xB0..=0xBA | nothing |

Gas is a statement about work. It was a statement about a different set of
instructions, and the set was written five different ways across the executor,
the verifier, the disassembler and the spec.

## The fix

The payload case reads `is_payload_opcode` with the stream's own framing flag — the
asset ops (`0x20..=0x25`) carry a payload only in a compiler stream, and in raw
bytecode they are fixed frames with nothing to read, so nothing to charge for. With
this, **classification and charging are one statement**; the *names* remain two
tables (TICKET-055), which is the last of the shape.

## Tested exactly

```
for every payload opcode: cost(64-byte payload) == cost(empty) + 2
```

"a longer payload does not cost less" is the natural weaker assertion and it passes
when nothing is charged at all — which is precisely the defect. The walk added last
round (`payload_opcodes()`, derived from the predicate) drives it, so a new
instruction is charged, or the test says so.
