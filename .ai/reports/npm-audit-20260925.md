# The npm advisories had no gate either, and 62 of them were sitting in 8 projects

2026-09-25. The Rust half of the dependency surface got enforced in the two preceding cycles
(`.ai/reports/dependency-audit-20260925.md`, `.ai/reports/dependency-deny-20260925.md`). This is
the JS half, which was in the same state: `npm audit` is the tool, nothing ran it, and GitHub was
reporting 87 rows across nine manifests that no gate could see.

## What was measured

`npm audit --json` in every project with a committed lockfile — 36 with `package-lock.json` and one
(`apps/x3-studio`) with `pnpm-lock.yaml`, so 37 projects rather than the nine Dependabot names. npm's
own view found **62 advisories in 8 projects**, including a critical and nine highs:

| project | before | after | how |
| --- | --- | --- | --- |
| `x3-app-store/backend` | 12 (6 high) | **0** | removed two dead deps, bumped express |
| `x3-app-store/frontend` | 8 (**1 critical**, 3 high) | **0** | `npm audit fix` + two overrides |
| `packages/polkawallet-bridge-adapter` | 26 (all low) | 26 (**accepted**) | no fix available; see below |
| `tests_core/wallet-integration` | 6 | **0** | removed a dead dep + overrides |
| `apps/explorer` | 4 | **0** | jayson override |
| `packages/ts-sdk` | 2 | **0** | jayson override |
| `packages/atomic-swap-sdk` | 2 | **0** | jayson override |
| `packages/blockchain-connector` | 2 | **0** | jayson override |
| `tests/wallet-integration` | 2 | **0** | jayson override |

The other 29 projects were already clean, including the pnpm one.

## The fix that mattered most: dead dependencies

Three of the findings were not really dependency *problems* — they were dependencies nothing used:

* `x3-app-store/backend` declared `axios` **and** `node-cron`; neither appears anywhere in
  `server.js` or `routes/`. `axios` alone accounted for 28 of the 87 Dependabot rows. Removing both
  took the project from 12 findings to 1, and the last one (a `qs` reached through `express 4.22.1`)
  went away by bumping `express` to the current 4.x.
* `tests_core/wallet-integration` declared `dappeteer@^1.0.0`, which peer-requires `puppeteer@^1.16`
  while the same manifest declares `puppeteer@^25.10` — so **`npm install` could not resolve at all**
  in that directory, and nothing noticed because the project is not in the JS test gate. `dappeteer`'s
  newest release is 1.0.0 (2019) and it is never imported, so it was removed and the install works.
* `packages/ts-sdk` declares `@solana/web3.js` but never imports it. That is what dragged in
  `jayson`/`stream-json`; the override below fixes the advisories, but the honest fix is to drop the
  dependency, which is left as a ticket because it changes a published package's dependency surface.

## The override that closed five projects

`@solana/web3.js@1.98` → `jayson@4.x` → `stream-json@1.9.1`, and `stream-json <= 3.4.0` is the
advisory. `npm audit fix` cannot help: jayson 4 requires `stream-json ^1`, and the fix is 3.5.0+.
**jayson 5.0.0 drops `stream-json` entirely**, so an `overrides` entry — the pattern these packages
already use for `esbuild`, `ws`, `minimatch` and others — clears it in one line.

Verified rather than assumed, because forcing a major version under a parent that did not ask for it
is exactly where this goes wrong: in `packages/ts-sdk` the full suite passes (185 tests) **and** a
runtime smoke test constructs a `web3.js` `Connection`, a `PublicKey` and a `Keypair` against the
overridden tree. The `js sdk tests` gate then passes for all five affected packages.

## What remains, and why

`packages/polkawallet-bridge-adapter` keeps 26 findings, all `low`, all `fix: False` for the roots.
They come from its **peer dependency** `@polkawallet/bridge@^0.0.2`, which pins an ethers v5 and
`@acala-network` stack; npm's own fix path is to remove the parent, which is the thing the adapter
exists to integrate with. They are recorded in `security/npm-audit-baseline.json` as an explicit,
ratcheted acceptance rather than left as invisible noise.

## The gate

`npm audit` (the gate) runs `scripts/check-npm-audit.py`:

* it audits every project with a tracked lockfile — 37 of them, ~22 seconds;
* **`critical` and `high` findings always fail and can never be baselined**, so the baseline cannot
  become a place to park something dangerous;
* `moderate`/`low` findings must be fixed or listed in `security/npm-audit-baseline.json`, and the
  ratchet runs in both directions: an unlisted finding fails, and a listed finding that npm no longer
  reports also fails, so an entry cannot outlive the exposure it describes;
* a project that cannot be audited (npm error, timeout, unreadable output) fails instead of being
  skipped quietly.

Verified by mutation: an unbaselined finding fails, a stale baseline entry fails, and restoring the
pre-fix `x3-app-store/frontend` lockfile fails with `axios is high; this severity is never allowed` —
the gate catches the exact critical that was sitting there this morning.

## Still open (ticket)

1. **Drop the unused `@solana/web3.js` from `packages/ts-sdk`** (and audit the other SDK packages for
   the same shape). That removes the whole jayson/web3.js subtree instead of overriding one node in
   it, and it is the fix that would protect *consumers*, since an `overrides` entry only applies to
   our own install.
2. **`tests_core/wallet-integration` has no test files at all** — a `package.json` and a
   `playwright.config.ts`, nothing else, and it is not in the JS test gate. Either write the tests it
   is named for or remove it; a test directory with no tests is the same shape as a gate that runs
   nothing.
3. **`x3-app-store` is not covered by any JS gate.** Its backend and frontend now audit clean, but
   nothing installs or runs them, and its `test` scripts are `echo 'No tests configured'`.
4. **npm audit needs the network.** The gate fails closed when it cannot reach the advisory service,
   which is the right default but means an offline gate box fails this gate rather than passing it.
