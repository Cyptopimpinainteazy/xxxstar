# X3Lang round 20 — 2026-09-18 — deterministic route optimizer (spec item 17)

Landed on `master` as `5caf0914b` (base `21cf9b2c0`). Spec build-order item 17.

## The requirement

PHASE 42 (DETERMINISM) is explicit about what an optimizer may depend on: no
unordered maps, no wall-clock jitter, no randomness, no thread scheduling, no
floating-point ambiguity, **no non-deterministic optimizer output**, no external
mutable state without proof. It prescribes stable ordering, bounded search and
canonical tie-breaking.

## Three decisions that make the output reviewable

**A tie is reported, not hidden.** Two routes can be equal on the objective and
differ everywhere else. The optimizer breaks the tie canonically *and says so*:
`decided_by_objective()` is false and `tied` lists what the objective could not
separate. A caller that believes the objective decided when a tie-break did has
been misled about the quality of the decision, not just its provenance.

**Infeasible names the blocking constraint.** `NoRoute::AllRefused` carries the
refusing venues and why each was refused, produced by the same `reject_reason`
the search calls — not a second opinion computed beside it. `NoRoute::None` is a
different value, so an unreachable route cannot be confused with a refused one.

**An exhausted budget is not an answer.** `search` now returns
`SearchOutcome::{Found, BudgetExhausted}` instead of a bare `Vec`. This was a
deliberate API break: it makes it impossible for a caller to report an
unreachable route for a search that never finished, and it is checked by the
compiler at every existing call site rather than by review. The hop bound alone
does not give a bounded search — a graph with many edges per node still explodes
— so the expansion budget is what makes the cost a property of the caller's
declaration rather than of the graph it is pointed at.

## Why the tie-break is the interesting part

Ranking is lexicographic: the objective's value, then the route's own venue list
compared as a sequence. The second term is what makes the output a function of
the *graph* rather than of the order the search reached things in. It is tested
by building the same graph twice with two tying venues declared in opposite
orders and requiring the same winner — a tie-break that depended on iteration
order would pass every other test in the file and fail that one.

## Scope note

The objective set is closed — `minimize_fees`, `minimize_slippage`,
`minimize_risk`, `minimize_latency`, `minimize_finality` — for the same reason
`atomic_choice`'s criteria are: the compiler can only optimize what it can rank,
and every member ranks on an integer a venue declares. "Maximize net profit"
needs amounts and prices, which the graph does not model yet, so it is absent
rather than approximated into the set.
