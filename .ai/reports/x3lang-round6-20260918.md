First feature commit of the session, after several rounds of hardening. The
phase ledger had phase 3 ("Economic effect system") and phase 4 as **ABSENT**;
both now have an implementation with tests.

## What landed

An atomic trade can declare what it does and what it promises:

```x3
atomic trade BorrowSwapRepay using EffectsDemo
    effects [borrow, swap, repay]
    guarantees [debt_closed, min_profit]
{
    borrow 1_000_000 USDC from aave_v3 as debt
    let weth = swap debt.amount USDC -> ETH
        via uniswap_v3
        min_out 1 ETH
    repay debt
    require net_profit >= 1_000 USDC
    require all_debts_repaid
    emit receipt
}
```

Both clauses are checked against the body: **every declared effect must be
produced by a statement, and every declared guarantee must be discharged by a
guard.** A claim the body does not keep is a compile error, not a comment. This
is the super-prompt's "the compiler could refuse to compile if an economic
effect isn't resolved", applied to the surface where debt and profit actually
live.

## Design decisions, and why

- **Closed vocabularies.** An unrecognized name is a parse error that lists the
  known set, following the precedent already set by `InvariantKind`. A label the
  compiler cannot check reads like a guarantee while meaning nothing.
- **Guarantees are restricted to what the compiler can discharge.** `debt_closed`
  from `require all_debts_repaid`, `min_profit` from `require net_profit >= <amount>`,
  `solvent` from `invariant solvent`. No guarantee is admitted whose enforcement
  would be a no-op — the same rule applied when the unenforceable policy ceilings
  were deleted in round 3. `principal_preserved` from the roadmap is *not*
  admitted, because nothing in the IR currently discharges it.
- **`swap` and `bridge` are accepted as clause names** even though both are
  lexer keywords. Rejecting a keyword there would have made the vocabulary
  unreachable for two of the four effects. The first implementation got this
  wrong; the tests caught it.
- **Both clauses are optional**, so no existing trade changes behaviour. The
  canonical fixture declares neither and there is a test pinning that.

Ten tests added: the AST round-trip, the parser's rejection of unknown names
(naming the known set), duplicates, and an empty list, the discharge check for
effects and for guarantees, that an unrelated set of clauses is unaffected, and
that omitting both clauses is fine.

One of the new verifier tests was initially **vacuous** — it asserted the
absence of an effect/guarantee diagnostic, which a parse error also satisfies.
It now asserts no `ParseError` is present first, so it cannot pass for the wrong
reason.

## Still missing for a complete phase 3

- `principal_preserved` and other roadmap guarantees need an IR-level meaning
  before they can be admitted.
- The guarantees are checkable *presence* properties: the compiler confirms the
  guard exists, not that it implies the guarantee. Tying `solvent` to the
  existing `AssertInvariant` semantics is done; tying `min_profit` to the
  policy's `minimum_net_profit` is not.
- No stable diagnostic code: the trading path emits `X3Error::SemanticError`
  with a message, while the coded `DiagnosticCode` catalogue only covers the
  parser, numeric and IR passes. Extending the catalogue to the trading path is
  a separate plumbing job (TICKET-021).
