`min_profit` needs a *floor* (`require profit >= 5`); written as a ceiling it says
the opposite, and the check reads the operator rather than just the number — the
distinction the previous commit's guard fix exists to preserve.

## Where the language stops, said out loud

A module body is the general statement language, which has no `borrow` or
`repay`. So `borrow`/`repay` effects and the `debt_closed` guarantee have no
statement that could discharge them, and a module declaring them is told exactly
that — a different answer from "you forgot to write it", and the message says
which. Debt belongs to an atomic trade, which has the statements for it.

`flash_capital` is the same limit from the other side: nothing in a module body
can *require* it, so declaring it is a capability the compiler cannot test.
TICKET-040 records it rather than adding a check that always passes.

## A gap the tests found

`allow intent_fusion` inside an `execute` block parsed as an expression statement
and vanished, so the permission check could never fire — the same shape as the
leg's `timeout` before it was routed through the clause parser. An execute block
now parses `allow` the way an intent body does.

## New ticket

**TICKET-040 — `flash_capital` cannot be tested.** Nothing in a module body
requires flash liquidity, so the permission is declarable and unverifiable.
Either a module body needs a borrow statement (which would also unblock the
`borrow`/`repay` effects and `debt_closed`), or the permission should be removed
from the set. Not decided here.
