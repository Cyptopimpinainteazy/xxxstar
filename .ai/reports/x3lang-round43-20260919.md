# X3Lang round 43 — 2026-09-19 — payload opcodes are walked, not assumed

Landed on `master` as `4e2890c63` (base `0d22540b6`). TICKET-055 partial.

## The test that could not notice

Last round's `InvalidOpcode(156)` had a test that should have caught it:
`all_capability_opcodes_reach_dispatcher` walked the *range*
`GPU_DISPATCH..=SUB_EXEC` and asserted each opcode had a name. That is the same
assumption as the bug — the executor's dispatch was written as that range — so an
instruction added to `is_payload_opcode` and not to the range was a payload opcode
to the verifier and an invalid one to the executor, and a range literal cannot
notice an opcode outside it. The test passed throughout.

## The walk

Two tests, both driven by the one predicate over `0x00..=0xFF`:

- **`every_payload_opcode_is_recognised_by_the_executor`** — no payload opcode may
  come back `InvalidOpcode`. The payload is deliberately empty: most of these
  refuse an empty payload, and that is the point — what is asserted is that the
  opcode *reached an arm*, which is the difference the drifting range hid.
- **`every_payload_opcode_frames_the_same_for_the_verifier`** — the verifier's walk
  must neither desynchronise (`OutOfBounds`) nor refuse the instruction
  (`InvalidOpcode`) for any of them.

## What writing them found

A **fourth enumeration**: the executor has its own `capability_opcode_name` table
beside the compiler's disassembler names, and the nonce instruction was missing from
it. The new name assertion caught it immediately.

A **fifth**: `gas_surcharge` charges `payload_len / 32` for
`0x20..=0x25 | 0x60 | 0x61 | 0x80..=0x9C | 0xA0..=0xAB`, which omits
`ATOMIC_CHOICE` (0x53), `ROUTE_FALLBACK` (0x54), `PARALLEL_PLAN` (0x55),
`STRATEGY_LICENSE` (0x57) and the trading range (0xB0..=0xBA) — instructions whose
payloads are read and dispatched by both the verifier and the executor. They are
charged a payload-proportional gas surcharge of zero. That is a *pricing* change to
make, so it is TICKET-056 rather than a quiet edit: it would move the exact-gas
figures the VM's tests and the corpus's `gas remaining` lines assert.

## Why the classification half is enough to claim progress

The predicate is now the single source for *which* opcodes carry payloads, and it is
walked. A new instruction that is added to the predicate and forgotten in a dispatch
arm fails the walk; one forgotten in a name table fails the name assertion. What is
still duplicated is description rather than classification — names and the gas
surcharge — and TICKET-055 says so rather than claiming the whole shape is fixed.
