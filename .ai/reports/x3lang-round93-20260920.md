## TICKET-109 + TICKET-108 — `4f322939d`

`lower_statement` ended in `_ => ir.push(Operation::Nop)`. `NOP` is written as four zero bytes, which
the compiler's instruction walker skips as padding and the VM's verifier breaks on as the end of the
stream — so every statement that arm caught was **dropped invisibly**.

| measurement | before | after |
|---|---|---|
| `x3c check tests/test_arithmetic.x3` | `3 ops, no semantic errors` (three `Nop`s; 16-byte artifact, no instructions) | ``semantic check failed: `let a = …` binds a name this compiler has no place to keep …`` |
| `if`/`for`/`return`/`break`/`continue` | dropped to `Nop` | refused by name, each with what is missing |
| bare `loop { … }` | dropped | lowered as `Loop { condition: True }` and refused by `while true`'s own message |
| corpus gate's "every `.x3` the tooling walks is a program" | satisfied by the artifact of the dropping for 3 files | the 3 files moved to `tests/sketches/`; the gate now means what it says |

The match is exhaustive with no catch-all, so rustc enumerates the missing arms — the next statement
variant cannot be dropped by default. `tests/test_arithmetic.x3b` (a committed one-byte file, `0x06`,
that no reader accepts) was deleted with them. `PLAN.md`'s ✅ "three `.x3` files compile through the
pipeline and execute on the VM" and its citation of `x3-lang/compiler/src/regalloc.rs` (a file that
does not exist; the linear-scan allocator is `crates/x3-opt/src/regalloc.rs`) are corrected — the same
false claim that made me look for a register allocator the compiler does not have.

TICKET-108 folded in because it is the same defect from the test side: `test_control_flow_e2e.rs`

## TICKET-099 — `7e23e3738`

A hedge is bounded by a **delta** and the bound travelled as a measured guard with the profit's mode
and the delta's unit code, so the simulation's mode-only reader refused every hedge artifact:

```
BEFORE  x3c simulate hedge.x3b --state hedge_within.json
        x3c: this artifact states a measured `delta` bound, which a simulation does not model: …
AFTER   x3c simulate hedge.x3b --state hedge_within.json --explain
        Delta: 1bps against a ceiling of 1bps — within
        Result: NO FLOOR STATED (net 0bps)
```

`ArtifactFloors.delta_ceiling_bps` (from the unit code), `SimulationSnapshot.delta_bps`
(`#[serde(default)]`, **`SNAPSHOT_VERSION` does not move** — the field is additive and optional, and
the one-way compatibility is the fail-closed direction), `SimulationError::DeltaUnstated`,
`Verdict::DeltaAboveCeiling` folding a *non-failing* verdict into a failure (including
`NoFloorStated`, the hedge's normal shape — the one combination where leaving it alone would have
been a silent pass), and the delta passed to the VM (it was `None`, an unreachable placeholder).

## TICKET-104 — `97d7af4f7`

`CompilerDiagnostic` has six fields and `into_error` kept two, because `X3Error` has no severity and
no secondary spans — faithful while every coded diagnostic came from `error`, and a trap the moment
one did not. Now: `CompilerDiagnostic::warning(..)`, `From<CompilerDiagnostic> for
x3_common::Diagnostic` (level, code, message, every span, help), `into_error`/`into_warning` each
asserting the severity they are for (both directions `#[should_panic]`-tested), and
`VerifyOutcome::push_diagnostic` — the one place the vector is chosen, from the diagnostic's own
field.

**The ticket's characterisation was wrong and the code records why**: it asks for the conversion on
the grounds that "the accumulator already accepts that type"; `VerifyOutcome.errors` and `.warnings`
are both `Vec<X3Error>`. Stated in the method's doc, because the next agent reads the ticket first.
**Not claimed**: no production pass emits a warning yet — the trap is closed, its first user is not
invented (candidate: TICKET-110's invisible `GasAdaptive` bodies).
