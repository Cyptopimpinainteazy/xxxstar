## What each one actually asserts

**(1)** The state records every credit, every debit and every cost per asset, so
`net_deltas = credits − debits − costs` is this accounting's conservation law, and no
balance exceeds what was credited. Both, per asset, over the host's output.

**(2)** Two halves, because "disappear" has two meanings. A committed trade carries a
closed record for the debt it opened at the principal it borrowed — the debt leaves a
record. A trade that did *not* commit closes nothing — the debt is undone rather than
vanished.

**(3)** The one worth reading twice. `balances` and `costs` are maintained by different
calls: `credit`/`debit` move the balance, `accrue_cost` records the cost and reduces
`net_deltas`. So

```rust
profit.net <= balance          // the profit is at most what the asset holds
balance - profit.net == costs  // and the gap is exactly what was charged
```

is a cross-check of two independently maintained fields. The first draft asserted only
that a passing floor implies a delta at or above it, and `TradingVm::profit` reconciles
the assembled figure against `net_deltas` before returning it — which made that draft
near-tautological. **The test was replaced, not kept**, because a property test that
cannot fail is a claim, not evidence.

**(4)** The identity over 256 generated cost lists drawn from all nine `CostKind`s:
`total_costs` is the sum of exactly what was declared — no category quietly outside it —
and `net` is the whole expression, including the principal and the safety buffer the
phase's shorthand omits. `gross == 0 ⇒ margin_bps == 0` is asserted too, from the
module's own documented rule.

**(5)** A plan that closes its debt and then opens the same id is refused, and the
refusal rolls the plan back.

**(6)** The fixture's repayment is removed, so the plan reaches `AssertAllDebtsClosed`
with a debt still open. The run must fail and leave no trace. This is the hostile
direction — the existing `success_never_has_open_debt_or_missing_commit` covers the
other one.

**(7)** `verify_evm_header_proof`'s anchor is two checks: the supplied `header_hash` must
be `keccak256(rlp_header)`, and it must be the *trusted* header's. Generated headers and
hashes exercise both, and each case pins **which** refusal came back:

| input | required refusal |
|---|---|
| self-consistent hash, but not the trusted header | `X3_EVM_HEADER_NOT_TRUSTED` |
| the trusted hash on bytes that hash to something else | `X3_EVM_HEADER_HASH_MISMATCH` |

Pinning the *code* is the point. A proof that gets past the anchor and fails later on
its shape is a proof that was trusted, and an assertion that only said `is_err()` would
pass on that. No mainnet fixture is needed: the property is about the anchor, and a
generated header exercises it with inputs no fixture happens to contain.

**(8)** A program naming a venue, or a provider, that the manifest does not declare is
refused, with the state rolled back — so the attempt leaves nothing behind.

## What is left

PHASE 48 — the adversarial matrix — is the last depth row. Its list is 30 cases, and the
ledger's own note is that x3-lang is missing the ones a *restart* implies: reorg
simulation, nonce conflict, restart during execution, process kill, RPC outage, partial
domain outage, dropped and duplicate transactions, ledger corruption. Those are the
interesting ones because the existing negative tests are all about a single process
deciding what to do with a bad input, not about state that outlives the process.

safety proof). PHASE 39 is complete except for artifact provenance (TICKET-075), and
