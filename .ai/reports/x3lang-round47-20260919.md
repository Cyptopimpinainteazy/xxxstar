# X3Lang round 47 — 2026-09-19 — `bridge_liquidity` against the declared bridges (TICKET-049)

Landed on `master` as `b6a9a231d` (base `cdae5ea23`).

## The guard

`require bridge_liquidity >= N` asserts the bridges this program uses can absorb N.
A `venue { kind bridge … liquidity … }` declaration is where a program states a
bridge's depth, so the claim is decidable — the same shape as `solver_bond` against
`solver_market` and `relayer_quorum` against `relayers`:

- **every** declared bridge must be at least as deep as the guard requires. Every one
  rather than any one: a route may take whichever the planner finds, so a depth
  requirement that held for one and not another would be a claim the program cannot
  keep.
- The refusal names the bridge and its depth: `requires 100000 of bridge liquidity,
  and the bridge 'thin_bridge' declares 1000`.
- A program that declares no bridge at all is told the guard has nothing to compare
  against.
- A ceiling instead of a floor is refused (`a liquidity guard is a floor`), and a value
  the compiler cannot read as a number says so rather than passing.

## The test that keeps moving

`a_known_kind_with_no_checker_yet_is_not_refused_here` asserts that a *known* kind
without a checker is not refused as an unknown one. Its example was `route_score`,
then `bridge_liquidity` — both gained checkers — and it now uses `audit_gate`. The
test's premise is a kind that has none, so the kind it uses has to move with the work;
worth noting because a stale example there would quietly stop testing anything.

## Guard kinds, after this round

**Ten of thirteen decided**: `solver_bond`, `relayer_quorum`, `canonical_supply`,
`proof_complete`, `refund_path`, `route_score`, `vm_supported`, `invariant`,
`bridge_liquidity`, and `nonce` by a run-time comparison. `slippage` and `profit` are
partial (`slippage`'s bound is checked against the declared profile; the *realised*
slippage has no source).

Remaining unbacked: `finality`, `risk`, `mainnet_safe`, `audit_gate`. Each needs a
declaration the language does not have — a chain's finality depth, a risk score,
evidence that the mainnet checks ran, an audit — and TICKET-049's per-kind criteria
exist so that none is invented one value at a time. That is the honest end of this
line of work without a language change that adds those declarations.
