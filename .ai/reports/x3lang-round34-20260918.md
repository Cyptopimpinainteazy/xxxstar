# X3Lang round 34 — 2026-09-18 — a guard can require a property (TICKET-045)

Landed on `master` as `f8b2e3bf0` and `1dcd17d58` (base `388793614`; two docs
commits from the merge queue landed mid-round and this branch rebased onto them).
Closes TICKET-045.

## What was broken

`require proof verified` did not parse:

```
$ x3c check examples/arb_solana_eth.x3
x3c: lowering failed: Parser error: expected expression
```

A guard's value was mandatory, so `parse_require_guard` read the second word as
the guard's *subject* and then demanded a value the program never wrote. It was
the only thing keeping `arb_solana_eth.x3` — 19 lines, written in the current
dialect — out of the corpus.

## The six shapes

| written | means |
|---|---|
| `require mainnet_safe` | a property of the program; no subject, no value |
| `require canonical_supply USDC` | a property *of* USDC |
| `require slippage 50` | a threshold of 50 |
| `require finality.sol == finalized` | an explicit subject |
| `require finality Ethereum >= 64` | a subject with a comparison |
| `require nonce unused <id>` | a subject *and* a value |

The two-token form cannot be told from `<kind> <subject> <value>` by looking at
one token, so it is decided by what the token *is*: a name is the only thing that
can be a subject, so `canonical_supply USDC` is about USDC, while `slippage 50`
is a threshold. `require slippage` — a bound with no bound in it — is refused, as
is `require nonce unused`, whose reader (the replay-protection rule) looks for
the identifier.

## Two things the first cut got wrong, and how they were found

**A guard must not swallow the next clause.** `require proof_complete` followed by
`amount 500` in an `atomic swap` body parsed as a guard *about* the word
`amount`, leaving `500` behind as a statement. It parsed, compiled, and produced
a swap with no amount. The prediction that this would fail loudly was wrong: a
bare `500;` is a valid statement in that body. Found by probing both clause
orders, not by a test — and it is why `CLAUSE_WORDS` exists.

**A bound kind must state a bound.** The kinds whose readers compare a value
(`slippage`, `profit`, `finality`, `nonce`, `relayer_quorum`, `solver_bond`,
`bridge_liquidity`, `route_score`, `risk`) cannot be written without one: a
reader that found `None` would take its "nothing to check" branch, which is the
one answer that makes a check disappear. `RequireKind::asserts_a_property` names
the eight that assert instead, and a bound kind without a value is refused at the
parser **and** again in `lowering::guard_condition`, so a hand-built AST cannot
lower an unconditional requirement either. A property guard lowers with the name
it asserted as its condition (`Condition::Expression { expr: "USDC" }`), not to
`Condition::True`.

## What this round did not do

- **`arb_solana_eth.x3` parses and does not compile**, and that is now recorded
  rather than skipped: `tests/test_formatter_roundtrip.rs` carries a named list of
  files the parser reads and the compiler refuses, and a new one fails the test.
  Its errors are its own: `min_output 0.09` and `10.25` are not integers the
  checks can compare, and the bridge is written from an asset no `from` clause
  funds, so the amounts lower to zero. Whether the *example* is wrong or
  fractional amounts are meant to work is TICKET-047.
- **TICKET-046**: `CLAUSE_WORDS` is a list that has to stay in step with the
  clause vocabulary. It is derived from the parser's own arms (only the words
  that arrive as identifiers, since keywords cannot begin an expression either)
  and both of the words that bit this change are covered by tests, but the real
  fix is for clause words to be lexer keywords so a guard stops at one without a
  list.
