# X3Lang round 3 — 2026-09-18 — policy honesty + quote freshness

Merged to `origin/master` as `771955972`, fast-forward from `aeddee6cf`
(`origin_only=0 branch_only=1`). 16 files, +381/-68.

## The defect

`CompiledTradingPolicy` carried four fields that the lowering pass **built by
aliasing unrelated source fields**:

```rust
max_total_cost:         max_gas,
max_price_impact_bps:   policy.max_slippage_bps,
max_mev_leakage_bps:    policy.max_slippage_bps,
quote_freshness_blocks: deadline_blocks,
```

`TradeRiskPolicy` in the AST declared none of them, so no source program could
set them. `rg` found them read in exactly one place —
`EconomicPolicy::validate_not_weaker_than` — which compared each against a copy
of itself. The "runtime policy cannot weaken the compiled policy" guarantee was
therefore partly checking fabricated numbers.

## Resolution: three deleted, one made real

### Deleted

| Field | Why enforcement would have been fake |
| --- | --- |
| `max_total_cost` | A bare amount with no denomination asset. Given one, it would duplicate `max_gas` + `max_gas_asset`, which already caps the whole per-asset cost bucket. |
| `max_price_impact_bps` | `SwapResult`/`QuoteResult` carry no price-impact figure. Enforcing it meant inventing a host field and comparing fabricated numbers. |
| `max_mev_leakage_bps` | Same — no MEV-leakage evidence exists at the host boundary. |

This follows the precedent already set twice in this repo: the Solana finalized
verifier and the Bitcoin vault-signer threshold were both removed rather than
left as unenforceable claims.

### Made real: `quote_freshness_blocks`

Quote freshness is the one that *could* be enforced, so it was:

- **Source syntax.** `quote_freshness: <blocks>` in a `risk policy`. Opt-in
  `Option<u64>`, shaped like `max_oracle_deviation`. Zero, fractional and
  non-integer values are rejected with a diagnostic that says to omit the field
  instead of declaring a zero ceiling; duplicates are rejected; omitting it
  means no bound.
- **Real evidence.** `QuoteResult` gained a required `quote_block`. A host that
  cannot say when its price was valid has no business satisfying a policy that
  bounds quote age.
- **Enforced before the swap.** `TradingVm` rejects a quote older than the
  ceiling with `TradingExecError::QuoteStale { age_blocks, ceiling_blocks }`,
  and does so *before* `host.swap()` is invoked — proven by a test asserting
  `host.swap_calls == 0` on the stale path, so a stale price cannot cause a
  host-side value movement that then has to be unwound.
- **Cross-chain safe.** A quote block ahead of `current_block` saturates to age
  0. A destination-chain venue does not share a block clock with the policy
  chain, so a "future" quote block is an ordinary reading, not staleness. The
  caller owns the obligation to tie `current_block` to the quote's chain, which
  is documented on the field.
- **Still covered by the strength check.** Relaxing the ceiling to `None` is
  refused as a weakening; tightening it passes. `Option` semantics are handled
  by a dedicated `quote_freshness_is_weaker` helper with its own unit tests,
  because `None` means "no bound" and is therefore weaker than any concrete
  ceiling while `(None, None)` is not a weakening.

Thirteen tests added, all named and confirmed executed:
`quote_freshness_is_optional_and_parses_when_present`,
`duplicate_quote_freshness_is_rejected`,
`a_zero_or_fractional_quote_freshness_ceiling_is_rejected`,
`fresh_quote_within_the_ceiling_commits`, `stale_quote_is_rejected`,
`stale_quote_aborts_before_the_host_is_asked_to_swap`,
`a_policy_without_a_quote_freshness_ceiling_does_not_check_age`,
`a_quote_from_a_higher_block_is_not_treated_as_stale`,
`dropping_the_quote_freshness_ceiling_is_a_weakening`,
`a_stricter_quote_freshness_ceiling_is_allowed`, plus three unit tests for
`quote_freshness_is_weaker`.

## Not done here

`max_price_impact_bps` and `max_mev_leakage_bps` are gone rather than
implemented. Bringing them back as real features needs host-reported evidence
first (a price-impact figure on `SwapResult`, an MEV-leakage figure on
`SwapResult`), plus a source key and enforcement — see TICKET-016.
