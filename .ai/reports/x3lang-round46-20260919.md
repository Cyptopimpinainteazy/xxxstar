## `vm_supported` against the program's adapters

The guard asserts the artifact runs on a VM family, and a program says which
families it uses in its `vm`, `target` and `venue` declarations — so the claim has a
compile-time answer:

- the named VM must match a declared `vm { adapter … }`, `target <vm>` or venue
  `domain`;
- compared through the family map the parser already uses for chain prefixes, so a
  guard's `solana` matches a declared `svm` (and a declared `sol` matches either).
  The families are the language's closed set; comparing the spelling would refuse a
  correct program over a word;
- a guard naming nothing is refused — every program runs on some VM, so
  `require vm_supported` says nothing;
- a program with no such declaration is told that, rather than given a vaguer error.

## `invariant` against the declared invariants

An invariant is checked because the program *declares* it — `invariant <name>` is the
rule the invariants pass reads — so a guard naming one the program never declares asks
for a check nothing provides. Same shape as `proof_complete` against
`proofs required`: declared → satisfied, undeclared → refused naming both sides,
nothing declared → told, naming nothing → refused.
