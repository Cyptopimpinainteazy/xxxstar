## 1. `require relayer_quorum >= N` is checked (TICKET-027, guard half)

`relayers { quorum N_of_M }` says how many relayers must attest;
`require relayer_quorum >= N` asserts a minimum. Nothing connected them — the
guard was only checked for being a positive integer, so `require
relayer_quorum >= 3` next to `quorum 2_of_3`, or next to no swarm at all,
compiled and ran. Same shape as the solver bond closed in `f2b972a3c`, same
reason it is a compile-time check.

While mirroring that check: the solver-bond version walked only
`Item::IntentDecl` body statements. Guards also live in the `requires` list of
`bridge`, `atomic swap`, `strategy` and `proposal`. A guard in any of those
escaped it silently. Both checks now share one `require_guards` enumeration,
and `relayer_quorum_guards_are_checked_wherever_they_live` exercises the
atomic-swap location so the next guard location cannot be added unnoticed.

Measured effect on the corpus: `examples/atomic_swap.x3` now parses (it did
not reach semantic analysis before) and reports exactly the missing
declaration instead of a parser-level stop. Still 9 clean of 16, 0 runtime
failures.

## 2. The verify-before-execute guarantee had a second door

`VM::execute` verifies then runs. The function it calls,
`x3_lang_vm::executor::execute`, was `pub` and verified nothing — so any
integrator could import the executor directly and skip the verifier.
`execute_unverified` was already `pub(crate)`, which shows the intent; the
identically-named public function just undid it.

`executor::execute` is now `pub(crate)`. The three callers outside the crate
now use `VM::execute`, which means those end-to-end tests prove their bytecode
passes the verifier as a side effect — they did not before, and they pass.

New negative case: `vm_execute_verifies_before_it_runs_anything` feeds the VM
an opcode the verifier does not know and asserts `X3_VERIFY_FAILED` with gas
and pc untouched.

Recorded because it cost a run: the first version of that test used `0xFF` as
the unknown opcode. `0xFF` is `HALT`, the verifier accepts it, and the VM
halted cleanly. The test was wrong, not the code. The constant now carries the
reason it is `0xAC`.

TICKET-026 asked a different question and its premise was false:
`x3_lang_vm.rs` is not callerless and `X3LangVm` does not exist. The ticket
was written from a path rather than a call-site search.
