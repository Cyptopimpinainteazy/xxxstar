# X3Lang round 17 — 2026-09-18

One commit on `origin/master`: `107fb463a` (base `520e53557`).

Seven defects, all one shape: a value or a check that exists upstream and never
reaches the thing that needs it.

## A correction to round 16's evidence

Last round I reported "the 9 corpus examples have no warnings under `check`".
That was wrong, and the way it was wrong matters. I measured with
`x3c build --deny-warnings`, and `--deny-warnings` was only honoured by
`check` — so the flag was accepted, ignored, and everything looked clean. The
second measurement (parsing `check`'s JSON with a one-liner that threw on the
trailing output and printed nothing) failed silently and read as "no
warnings". Five of the nine buildable examples warn. Both the tool and my
reading of it produced a false green in the same round.

## What changed

1. **`--deny-warnings` was honoured by `check` alone.** `build`, `deploy` and
   `receipt execute` accepted it and dropped the warnings. One
   `compile_with_mode_diagnostics` keeps them on the build path, one
   `report_warnings` reports and enforces. TICKET-032, closed.
2. **`atomic swap` / `bridge` timeouts rejected `40m`.** The lexer hands a
   suffixed duration back as an identifier; the intent path read the digits off
   the front and the atomic-swap path parsed it as an integer. Both now go
   through one `timeout_expression_to_blocks`, which also stops a u128→u32 cast
   from wrapping a large literal into a short timeout.
3. **`ON_TIMEOUT` discarded `duration_blocks`.** It emitted register index 0
   and the executor read `r0` as the deadline, so the timeout was register
   residue: `atomic_swap.x3` failed with "deadline 0" where `simple_swap.x3`
   passed on the same opcode. The deadline is the instruction operand now, and
   zero means "no instruction budget" — `duration_blocks` counts blocks and
   this VM has no block height, so using it as an instruction budget would
   bound a program by its size rather than its behaviour. TICKET-034, closed.
4. **`receiver sol.wallet.owner` lowered to a Rust debug string.** The dotted
   path fell through `expression_to_string`'s `_ => format!("{:?}", expr)` and
   became `FieldAccess { target: ... }`, which the name check then rejected as
   too long and full of unsafe characters.
5. **`check_safe_symbol` rejected `.`**, so the documented dotted-path receiver
   could not be written. Dots are allowed between non-empty segments; a `..`
   segment is still refused, so no traversal is opened.
6. **Proof requirement gated on `Bridge`, not `Lock`.** TICKET-024. A
   same-chain intent is no longer asked to prove it locked funds on a chain it
   never left. A bridging program must still declare both proofs.
7. **`no_double_refund` and `no_refund_after_claim` counted globally.** A
   two-legged swap refunds `eth.USDC` on the source timeout and `sol.SOL` on
   the destination timeout — two locks. Both rules now reason per lock.

Corpus side: five programs now declare the proofs their bridge depends on, and
`examples/atomic_swap.x3` — the roadmap's own example — declares the relayer
swarm its quorum guard asserts, then builds and runs.

## Test integrity

- `GOOD_SOURCE`, the fixture behind both `--deny-warnings` tests, is a
  *same-chain* intent whose only warning was defect 6. The tests asserted that
  the compiler complains about a correct program and were green because of the
  bug. Replaced with a bridging fixture that warns for a correct reason.
- `compile_program_with_regalloc_runs_full_pipeline` had an unreachable `Ok`
  arm; its `alloc.len() == 0` assertion had never been evaluated, and stops
  being true once the pipeline succeeds. It now asserts what regalloc owes.
- Both are the same lesson as the `--deny-warnings` false green: an assertion
  that cannot fail is not evidence.

## Known open, and why it is not fixed here

`examples/atomic_swap.x3` emits one `no_refund_after_claim` warning. The rule
cannot do better over this IR: `Operation::Release` means both "claim an
escrowed lock" and "pay out the swapped asset", so a structural scan cannot
tell a double-spend from a two-legged swap. TICKET-035 needs the IR to
distinguish them.

TICKET-033: a timeout unit suffix is accepted and ignored — `40m` is 40 blocks.
Changing it moves the timeout-ordering invariant for every compiled program,
so it is a settlement-safety decision with its own acceptance criteria, not a
patch.
