## The gates

`compiler/tests/test_determinism_audit.rs`, three tests over `compiler/src`, `vm/src`
and `crates/{x3-ast,x3-common,x3-lexer}/src`:

**1. No clock, no random source, no spawned thread — absolutely.** Nine patterns, no
allowlist, because the tree has zero of them. The gate asserts it read more than 20
source files first, so a wrong path cannot make it vacuously pass.

**2. The same source compiles to the same artifact, eight times.** This is the property
the phase actually wants, asserted directly rather than inferred: a source scan cannot
see a clock reached through a dependency, and this can.

**3. The word-boundary helper has its own test, and it is not decoration.** Plain
`contains("rand::")` matches `Operand::Reg(r)` — so the first version of this audit
reported two violations in a comment about register operands and **none** of the real
thing:

`contains_word` requires the preceding character to be non-alphanumeric, and
`the_word_boundary_helper_rejects_the_false_positive_it_exists_for` pins both the
match and the non-match. A text gate with a false positive is a text gate that gets
turned off.

## The finding the survey produced

`compile_program_with_regalloc`'s doc said:

> This is the entry point that promotes `regalloc::allocate` from a library-only
> function to a real pass in the production compilation pipeline. Without it, the
> linear-scan allocator at `x3-lang/compiler/src/regalloc.rs` is dead code as far as the
> compiled binary is concerned.

The second sentence is true. The first is not:

| claim | reality |
|---|---|
| "a real pass in the production compilation pipeline" | `regalloc::patch_operation` is an **empty function**; `rewrite_operations` carries `#[expect(dead_code, reason = "v0.2 register allocator placeholder")]` |
| reached from the production path | called **only from this module's own tests**; `x3c build` uses `compile_program` |
| the allocation is consumed | `vm/src` never mentions `register_assignments` or `spill_slots`; `let _alloc = allocate(...)` and the result is returned to a caller nothing calls |

This is TICKET-065's defect class — a doc asserting a wiring that is not there — inside
the compiler this time, and it is PHASE 42's "non-deterministic optimizer output" item
inverted: the optimizer's output is discarded entirely, which removes the risk and also
means the phase's "canonical tie-breaking" has nothing to bite on for the allocator.

What landed is the measurement, not the wiring:

```rust
the_regalloc_entry_point_emits_the_same_bytes_as_the_plain_one
```

asserts the artifact from the regalloc entry point is **byte-identical** to
`compile_program`'s, and that the allocation record mirrors the IR it was handed. It
**passes**, which is the measurement. It is a **ratchet**: it fails the moment the
rewrite is wired, which is exactly when the doc comments on
`compile_program_with_regalloc` and `regalloc::rewrite_operations` have to stop saying
"placeholder". A half-wired allocator cannot move consensus-relevant bytecode
unwatched. **TICKET-085** records what wiring it needs.

## What is still not gated, named rather than implied

The test file's module doc lists all three, with their evidence, so a reader cannot
mistake this round for the whole audit:

- **unordered maps (TICKET-086)** — a survey of the iteration sites, not a
  classification of all 68. The one iteration found is `temp_to_reg.values().any(|&v| v
  == *r)` in `regalloc.rs`, which is an existence test and therefore order-independent;
  the others are keyed lookups and membership tests. That is *consistent with*
  determinism and is not proof of it.
- **floating-point ambiguity** — PHASE 43's `crates/x3-common/src/fixed.rs`, whose audit
  list is answered item by item in `crates/x3-common/tests/fixed_math.rs`, and the one
  live `f64` is a Solana wire field documented at the field.
- **external mutable state without explicit proof** — PHASE 44's fail-closed half: the
  measured guards refuse with `X3_GUARD_UNMEASURED` rather than comparing whatever a
  register happens to hold.

## Ledger status, stated honestly

PHASE 42 stays **PARTIAL**, not DONE. The mechanically decidable half is now a gate and
the optimizer half is now measured, but "must never depend on unordered maps" is
verified by a survey and a survey is not an audit. It becomes DONE when TICKET-086's
per-site classification exists, and not before — a `17/23`-style number read as a
baseline is exactly the habit this round is trying to break.
