# X3Lang round 31 — 2026-09-18 — profit as a first-class value (spec PHASE 5)

Landed on `master` as `f44df9e4a` (base `28496cd67`). Closes GAPS-2.

## What PHASE 5 asked for, and what was there

"Profit must not be represented as an arbitrary integer", with the decomposition
`gross - principal - gas - dex - flash - protocol - settlement - hedging - buffer
= net` and the accessors `p.gross`, `p.cost`, `p.net`, `p.margin`, `p.realized`,
`p.unrealized`.

The language already had the *pieces* — typed cost kinds behind a fail-closed
allowlist, a signed per-asset delta, a cost ledger recording every committed cost
with its category — and assembled none of them. The floor was checked against a
`u128` clamped at zero, so a loss read as "profit 0".

## The value

`vm/src/profit.rs`. One field per `CostKind`, exhaustively matched, so a new kind
does not compile until it has somewhere to go; `net` as `i128`; `margin_bps`
computed in integers (PHASE 43 forbids a float in a share of money). A cost kind
the type does not know is **refused** rather than omitted: omitting it would make
`net` larger than the trade earned, which is the worst possible direction for an
error in a profit figure.

Two quantities from the spec's list are absent and say so — `hedging_costs()`
returns `None` because no hedging is modelled, `unrealized()` returns `None`
because it needs a price this path has no oracle for. A zero field would claim a
hedge happened and cost nothing.

## The decomposition is reconciled, not merely computed

`net = credits - debits - costs` is an identity of this accounting. So
`TradingVm::profit()` assembles the parts and then compares its `net` against the
recorded delta; a disagreement is `ProfitReconciliationMismatch`, a typed error
naming the asset and both figures. Two computations of one quantity that disagree
mean a movement or a cost was written in one place and not the other, and taking
either side would be a guess. The state tracks credits and debits per asset to
make the reconciliation possible.

## Two defects the wiring exposed

- **The policy-level floor check took the maximum delta across every asset**, so a
  trade that lost on the settlement asset passed whenever a side asset gained.
  It now reads the asset the floor is denominated in.
- **`minimum_net_profit` was a bare number with no asset** — the same problem
  `max_gas_asset` exists to solve, one field over. `CompiledTradingPolicy` now
  carries `minimum_net_profit_asset`, lowered from the amount expression that
  always had it, and a floor without an asset is `NetProfitFloorWithoutAsset`.

`EconomicPolicy.minimum_net_profit` is `Option<u128>` now, because flattening it
to `0` made "no floor declared" and "a floor of zero" the same policy — and with a
signed net that difference is real. The existing weakening comparison already
orders `None < Some(_)`, so dropping a floor is still caught.
