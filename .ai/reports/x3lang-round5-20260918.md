## 1. The builtin invariants were measuring the wrong thing

Four of the six rules reasoned about linear position in the whole operation
list. Intent lowering emits `from`/`to` endpoints **before** the route body and
the failure handler **after** it, so position in that list is not execution
order. Measured before: `internal_swap.x3` 4 violations,
`timeout_refund.x3` 4, `mainnet_safe_swap.x3` 1, `flagship_b52.x3` 1 — every
well-formed bridging intent in the repository looked broken.

`atomic_scoped_operations` returns the operations that execute *inside* an
atomic route body, walking `If`/`Loop`/`Simulate`/`ScheduledDispatch`/
`GasAdaptive` bodies so a claim nested in a branch is still seen. The four
positional rules now evaluate over that view, and
`destination_fill_before_source_claim` is skipped when the route contains no
bridge, since a same-chain route releasing its own escrow has no fill to order
against.

`no_double_refund` and `no_route_mutation_after_lock` stay program-wide —
handler cardinality and route-mutation-after-lock are properties of the
program. `no_double_refund` now also counts on-fail refunds, so "at most one
refund handler" holds across both handler kinds.

Measured after: **0** invariant warnings on all four programs.

## 2. The proof requirement could not be satisfied by any correct program

`verify_proof_requirements` demanded the exact names `lock_proof`, `fill_proof`
and `claim_proof`. Those names appear in **zero** `.x3` files in the repository;
the vocabulary programs declare is `source_lock_proof`,
`source_finality_proof`, `destination_fill_proof`,
`destination_finality_proof`, `solver_signature`. Proof names are free-form
symbols, so the check now classifies by category with substring matching, which
accepts both the canonical form and short variants.

`claim_proof` is dropped rather than renamed: nothing declares it, and the
destination-fill proof is what authorises a release. Requiring the name was the
same defect a third time. What a release *should* prove is a design decision —
TICKET-018.

Measured: `mainnet_safe_swap.x3`, `flagship_b52.x3` and `intent_with_proofs.x3`
go from 3 warnings each to **0**, and `x3c --deny-warnings check` now passes the
flagship example.

## 3. An unrecognised intent clause was silently ignored

Chasing why `intent_with_proofs.x3` still warned after the vocabulary fix
surfaced a worse bug: its `proofs required { ... }` block sat **inside** the
intent body, and `parse_intent_clause`'s fallback parsed anything unrecognised
as a generic expression statement, which lowering then dropped. The fixture
declared five proofs and produced **no** `ProofRequired` operations at all.

The fallback now rejects any clause outside the documented set. A nested
`proofs` gets a diagnostic naming file scope as the correct place. The fixture
declares its proofs at file scope, which is where the working examples already
put them. Six new parser tests cover the rejection paths and the file-scope
acceptance.
