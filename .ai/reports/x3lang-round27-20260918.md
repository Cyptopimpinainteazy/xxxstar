# X3Lang round 27 — 2026-09-18 — licensing, royalties, profit splitting (spec item 23)

Landed on `master` as `82325398f` (base `a9a72d086`). Spec build-order item 23,
PHASE 24 and 25.

## What a module can now say

```
license { creator x3_strategy_author profit_share 3% executions 10_000
          expires_block 88_000_000 }
split profit { 92% -> trader  5% -> liquidity_provider  3% -> strategy_author }
```

## The checks that make the two mean something

- **the split must total exactly 100%.** A split that does not add up is
  distributing something it does not have, or quietly leaving profit unassigned;
  the error states the total it found.
- **the royalty must be a share the split pays.** A licence granting the author
  3% beside a split paying 1% is a promise the artifact does not keep. A licence
  granting a share with no split at all is the same promise one step earlier.
- **a split needs a profit floor.** PHASE 25's "distribution should occur only
  after final net profit is known" means, concretely, that without
  `require profit >= <amount>` there is no net profit for the split to apply to.
- **recipients are a closed set.** Free-form handles would make the royalty check
  impossible, because "does the author get paid" would depend on a name happening
  to match one in the licence.

Shares are basis points internally (a share is money; PHASE 42 forbids
floating-point ambiguity in anything that moves money). The surface takes whole
percentages, and `99.5%` is refused with a message saying a share finer than one
percent is not expressible yet rather than being silently rounded.

## "Licensing must never compromise deterministic execution"

A property of the encoding, not of care: the licence lowers to
`STRATEGY_LICENSE`, a *record* no instruction tests, and both verifiers validate
it as a distribution plan without executing anything. `test_licensing.rs` asserts
the consequence directly — the executable stream is identical with and without a
licence, and only the record differs.

## Two bugs of mine, found by the tests

- A module with a split and no licence emitted a licence record with an empty
  creator, which the IR verifier then rejected, so an *unlicensed* split could
  not compile. A creator is now required only when a royalty is claimed.
- One diagnostic had a run of source indentation baked into it by a line
  continuation ("finer than one                          percent").

## A lexer inconsistency worth recording

`70%` and `0.5%` do not arrive as the same token: a whole percentage is an
integer followed by `%`, while a fractional one is a single `Percentage` literal
whose text still carries the trailing sign. The share parser handles both because
they are one construct to an author, but the split is in the lexer and not in
anything a reader would predict. TICKET-041.

## New ticket

**TICKET-041 — whole and fractional percentages lex differently.** `70%` is
`Int` + `Percent`; `0.5%` is a `Percentage` literal whose value carries a `%`.
One construct, two token shapes, nothing a reader would predict.
