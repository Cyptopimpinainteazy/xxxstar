# X3Lang round 45 — 2026-09-19 — one table names an instruction (TICKET-055)

Landed on `master` as `92c9c581b` (base `1c9d54812`). Closes TICKET-055.

## The last of five tables

Instruction plumbing had five places that described payloads: the classification,
the executor's dispatch, the gas charge, the gas/memory tables and the *names*. By
the start of this round the first four read `is_payload_opcode`; the names did not.

- `spec/opcodes.rs` gains `opcode_name(opcode)` — the file both crates `include!`,
  so the compiler's disassembler and the executor's diagnostics read one table.
  Every arm is written with the opcode's *constant* except `ADD`/`SUB`, which have
  none.
- The executor's `capability_opcode_name` is deleted (an instruction the nonce guard
  added had been missing from it).
- The disassembler's separate name table is deleted, and so is its own idea of which
  opcodes carry a payload: it held a `VECTOR` arm for `0x70..=0x7F`, **a range no
  instruction has ever been emitted in**.
- `decode_payload` treated the capability range as `0x80..=0x9B`; the nonce
  instruction is `0x9C`, so its payload printed as raw text. Extended.

The walk asserts that every payload opcode is both **recognised** and **named** — the
assertion that failed before this table existed.

```
$ x3c explain a.x3b
  0003  0x23  RELEASE      Release { chain: "solana", asset: "SOL", to: "wallet" }
  0007  0x9c  NONCE_UNUSED NonceUnused { nonce: "simple_swap_001" }
  0008  0x40  REQUIRE
```

## My own mistake, recorded

Deleting the executor's table, my script cut from the function's signature to the
next `\nfn ` and left the `#[cfg(test)]` attribute that had preceded it attached to
the *following* function — which took the host dispatcher out of the non-test build.
The compiler said so immediately, which is what a compiler is for; the fix was to
remove the orphaned attribute. Worth writing down because the same edit pattern
(delete a span of lines) is one I have used repeatedly on this repository, and its
failure mode is silent in the *source* and loud only in the build.
