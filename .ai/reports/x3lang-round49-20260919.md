# X3Lang round 49 — 2026-09-19 — a fractional amount is refused where it is written (TICKET-047)

Landed on `master` as `b6fff9dd1` (base `248b59c91`). Closes TICKET-047.

## The silent path

`expression_to_u128` has refused a fractional literal since PHASE 43 — an amount is
converted only when the conversion is exact, and the exact path goes through an
asset's declared decimals. But the swap lowering called the **non-erroring** wrapper:

```rust
input_amount: route.as_ref().and_then(expression_to_u128_opt).unwrap_or(0),
```

so `min_output 0.09` in `examples/arb_solana_eth.x3` reached the verifier as

    X3E0501: program[6]: swap min_output must be greater than zero

— a report about a zero, three passes after the literal that caused it, naming neither
the literal nor the reason. It now says what happened, where it happened:

    expected an amount, but `0.09` is a fractional literal; an amount is converted only
    when the conversion is exact, so write it in base units or use a field that carries
    its asset's decimals (as `max_gas: 0.02 ETH` does)

The two cases are distinct, which is the point: nothing written is 0 (and a floor of
zero is refused *for being zero*, with the verifier's own message), while something
written that cannot be converted is refused with the literal named.
`expression_to_u128_opt` had no other caller and is gone rather than left as the way to
spell "convert or pretend it was zero".
