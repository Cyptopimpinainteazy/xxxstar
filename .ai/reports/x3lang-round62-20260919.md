## TICKET-090 — the formatter wrote a comment where a percent literal was

Found by asking whether the fixed example was formatter-stable. `x3c fmt` produced:

```
    require slippage <= /* literal */
```

A **comment** in place of the literal — source the parser rejects, so formatting a file
could make it unparseable. The cause is the literal match's catch-all,
`_ => self.write("/* literal */")`, reached by `LiteralExpr::Percentage`. `require slippage
<= 0.5%` is the phase's own example, so the defect was live for any program with a percent
bound.

`Percentage` is rendered now. The other five variants it reached — `RawString`,
`ByteString`, `Char`, `Byte`, `Size` — have **no arm in the parser that produces them**, so
a parsed program cannot contain one; the fallback says so and carries a
`debug_assert!(false, …)`, so a hand-built AST reaching it fails loudly rather than being
silently rewritten. The round-trip test over `examples/*.x3` is what caught this, and it is
what keeps it caught.

## TICKET-091 — three drifts between two implementations, and a much larger boundary

Fixing and then reformatting the example made the Python surface in `cli.py` reject it
**three times**, each one a spelling the compiler or the formatter accepts and the surface
did not:

| spelling | where it came from |
|---|---|
| `proof_complete` | the compiler's name for what the surface called `proof` |
| `finality.<chain>` | what `x3c fmt` writes for `finality <chain>` |
| `refund <asset>` | what `x3c fmt` writes for `refund <asset> to sender` — the default receiver is `sender` |

All three are read now. Then the obvious gate — "the surface must read every example" —
showed the boundary is far larger: **sixteen of nineteen examples are refused**, and the
reasons are the surface's *scope*. (Round 63 corrected this figure: the first count said
thirteen and the list it came from had sixteen entries. The omissions are named here
rather than quietly fixed, because a number in a report is the thing a later reader
quotes.)

```
expected intent <name> {     seven examples start with finality_policy or risk_policy;
                             the surface accepts only a file whose first item is `intent`
invalid Ethereum address     it validates address shape (40 hex chars) and the examples
                             use short placeholders like 0xA1
malformed require 'route_score'   nine guard kinds here, eighteen in the compiler
list index out of range      four files crash the parser rather than being refused
```

`list index out of range` on four files is the one that is a defect rather than a scope
statement: **a parser that crashes on valid input has no error surface at all.** The rest
is a decision for whoever owns the surface — intentional scope, in which case it should be
stated, or a surface that is behind and should be caught up. TICKET-091 records both with
the enumeration.

So the gate shipped asserts what is *true*: `tests/test_surface_drift.py` derives from the
suite which examples it uses — rather than listing them, so a test that starts using a new
example brings it in — and requires the surface to read those. That pins
`arb_solana_eth.x3` and therefore all three drifts, without asserting a requirement the
surface does not meet.

**The lesson, and it is the round's:** a gate written against the *ideal* assertion failed
immediately and correctly, because the assertion was false. Writing it against the boundary
that exists, and recording the rest as a decision someone has to make, is the difference
between a gate and an aspiration.
