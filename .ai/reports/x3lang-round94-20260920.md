# Round 94 — 2026-09-20 — a runtime branch on a measured quantity, and the version byte per artifact

**TICKET-106 + TICKET-105 closed and pushed as `bb5737775`** (base `97d7af4f7`, which was master).
This is TICKET-058's remainder and the last construct the compiler refused by design.

## What was measured before and after

`if <condition>` was refused unless the compiler could decide it from literals. The quantities a `.x3`
program can *name* are the three a host measures, which the VM already holds — so the class is: a
comparison of `profit`/`slippage`/`delta` against a bound, in a branch position.

```
BEFORE  $ x3c build measured.x3
        x3c: … `if` cannot be executed — the condition is not decidable at compile time, and this VM
        branches on a register … (TICKET-058)
AFTER   $ x3c explain measured.x3b
          0005  0x34  IF_MEASURED profit >= 20bps, skip 2
          0006  0x88  MEMPOOL_SCAN             MempoolScan { max_results: 10 }
        $ x3c run measured.x3b --measured-profit-bps 25   → ok, gas remaining 999296  (body ran)
        $ x3c run measured.x3b --measured-profit-bps 5    → ok, gas remaining 999346  (body skipped)
        $ x3c run measured.x3b                            → X3_GUARD_UNMEASURED: the branch
                                                            `profit >= 20bps` needs a profit the host
                                                            measured, and no host reported one …
```

The 50-gas difference between the two runs is the skip working — the body's instructions cost gas, so a
run that skipped it has more left.

| piece | decision |
|---|---|
| instruction | `IF_MEASURED` = `0x34`, payload `<unit>:<invert>:<threshold_bps>:<skip>` |
| unit codes | the guards' own: 0 profit, 1 delta, and **2 newly named** for slippage (it had a mode of its own, so it never needed a code — a branch has no mode field) |
| shape | two records per branch, bodies between them; there is no unconditional jump in this format |
| skip | in instructions, written *before* the body: a body's byte length is offset-independent because every instruction starts on a four-byte boundary |
| evaluator | `measured_comparison`, shared with `REQUIRE`: failure = refusal in a guard, fork in a branch; **unmeasured = refusal in both** |
| IR | `Condition::Measured { quantity, comparison, threshold_bps }`, `MeasuredQuantity` naming each quantity's own direction |
| bounds | the guards' exact converter, so `0.005%` is refused as a half basis point |

## TICKET-105: the version byte is per artifact

`CURRENT_BYTECODE_VERSION` becomes the **ceiling** the writer may write (still
`== max_opcode_version()`, still a compile-time gate) and `emit_x3ir` narrows the byte to the greatest
version among the opcodes the artifact contains, read back out of the stream with the reader's own
framing. Measured: a program with no version-2 opcode writes `0x01`; one with `IF_MEASURED` writes
`0x02`.

**The change exposed a hole worth the ticket on its own**: with `is_defined_version` as the only gate,
a version-3 artifact from a future build would have been walked as *raw bytecode* — "nothing defines
version 3" is exactly the reasoning TICKET-097 exists to forbid. `is_reserved_version_byte` claims
`0x01..=0x0F`, so a reserved version this build does not know is a stream refused *by name*.

**And it introduced a bug two tests caught**, which is what they are for: `decode_trading_program`
demanded *exactly* the writer's ceiling, so it refused every trading artifact this build had just
compiled (`unsupported or missing bytecode version`). It accepts any supported version now.

## Not claimed

- The bodies are the statements a generic block accepts (`require`, capability calls). A
  statement-position asset operation is the route and `atomic_choice` grammars' to place, which is why
  the skip test builds its IR by hand.
- A measured branch chooses between *statements*, not between *plans*. Choosing plans by measurement
  is a design question this ticket did not open; `atomic_choice` remains the bounded form PHASE 12
  asks for.
